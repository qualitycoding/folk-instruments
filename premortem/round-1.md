## Incident report (simulated, 15 May 2027)

The pull request merged on 2026-12-20 with every check green and every `Done when` met: 27 Catch2 cases, 306 Python tests, five host tests and 20 pluginval logs on four runners, T-013 at 4.3 times real time, T-200 passing after three DR-07 rounds, and five listening gates answered `proceed`.

By May the owner had stopped using the plugins. The record shows how. The listening gates had passed on folk-render audio. The accordion scored 8 of 12 and the mandolin 7 of 12, which are the scores a listener who hears the difference about 70 % of the time gets half the time. Harmonica, melodion and bouzouki had no pairs, because Freesound was never searched, and passed on one line, `wrong: none`. The owner first used the actual VST3s in Ableton Live after the merge. The 3-day CI artifacts had expired, so they rebuilt them. On macOS the downloaded bundles were blocked by quarantine until they found the `xattr` command. In Live the harmonica's bends did nothing, because the wrapper's pitch-wheel scaling was off and no test sent a pitch wheel through the wrapper. The accordion distorted on every Master-register chord. A Live set saved on the owner's German-locale Windows laptop reopened with default sounds: the state text read `level=0,7`, and `loadState` refused it, exactly as D-090 requires. On another host every plugin came back as its first factory preset after a reload. A 192 kHz project crashed Live in `prepareToPlay`.

Meanwhile `main` had been red since February. The Philharmonia download URLs moved, `pip-audit --strict` reported a numpy advisory, and nobody was left to apply DR-08 or DR-11. Nobody could tell those failures from a real regression. No step had been skipped. Each check tested the core through folk-render, or tested whether a listener failed to tell real from synthetic. Nothing tested the shipped plugin in a host.

## Findings by lens

### 1. Technical correctness (DSP, numerics, real-time safety, state, the tests themselves)

- **The shipped wrapper is unverified in everything musical (F-1, High, plausible).** All audio tests, demos and pairs come from `folk-render`. `T-302` compiles `FolkProcessor.cpp` into a console program and puts one note-on into `processBlock`, so it never goes through the VST3 layer. A wrapper that passes normalised values (0 to 1) to `Engine::setParam` sets `a4_hz` to 415 Hz, and the state round trip of T-302 still passes. In VST3 the pitch wheel and the CCs arrive only through JUCE's MIDI-CC parameter emulation, which no test exercises. Lesson L-20261008T173530Z ("through the real processor") recurs.
- **State text depends on the locale (F-2, Critical, plausible).** D-090 prescribes `%.9g`, and T-014 and T-302 run only in the C locale. Under a decimal-comma `LC_NUMERIC`, set by the host or by another plugin in the same process, the saved state is refused as a whole, and the session silently reloads at defaults. S-ADVERSARIAL tests commas only as input and confirms the refusal.
- **A program change after a restore resets the state (F-3, Critical, plausible).** Factory presets are exposed as JUCE programs, and a preset sets every other parameter to its default. A host that re-applies the program parameter after `setStateInformation` therefore wipes the restored state. The current program is not part of the state text.
- **Rates outside 44.1 to 96 kHz are undefined (F-4, High, plausible).** `prepare` may throw, clamp the rate, or use the wrong reed-offset table. pluginval, T-160 and S-ADVERSARIAL all stay inside the range.
- **Wrapper threading (F-5, High, plausible).** D-094 allows "pushed into the engine" from `getStateInformation`, which reads naturally as the live engine. There is no concurrent stress test and no TSan build of the wrapper. Lessons L-20261101T140000Z and L-20261009T161100Z were applied to the core only.
- **T-011 never changes a parameter while armed (F-6, Medium).** It sets only default values, so an allocation on a register or variant change goes unseen.
- **Noise stages are tested by lower bounds only (F-21, Medium).** Lesson L-20261009T120012Z recurs.
- **Gain staging (F-22, Medium).** Gain is calibrated on one note in one register, and chords drive the `tanh` limiter into distortion. No check bounds the true peak (lesson L-20261009T090804Z).
- **String aliasing under an upward bend (F-23, Medium).** The partial count is fixed when the stroke starts.
- **Speculative (F-33).** If D-011's sub-step count is not recomputed when `a4_hz` moves during a note, steps per period can fall towards the divergence limit, and D-015 then silences the voice without any test failing. Later rounds need not rediscover this; it only needs one sentence in D-011.
- **The suite cannot tell physics from an imitation (F-31, Medium, remote).** C-056 shows an additive stand-in passes the behaviour tests. The model's identity is checked only through `reed_probe`, which need not share the engine's code path.

### 2. Dependency and supply-chain drift

- **gate-evidence holds a write token across unpinned installs (F-14, Critical, remote).** `contents: write` is granted for the whole job, and checkout persists credentials by default. The job then pip-installs unhashed transitive dependencies and runs repository code, while `main` has no protection.
- **Wheels verified on Linux only (F-20, High, remote).** The numpy and scipy wheels were confirmed only on Linux (C-048), while the core job installs them on macOS Intel and Windows before configuring.
- **Post-delivery decay (F-13, Medium, expected).** External data, `pip-audit --strict`, runner-image updates and unpinned transitive dependencies turn `all-green` red with no change to the code. R-006 covers only a label retirement during implementation.
- JUCE, Catch2, pluginval and the actions are pinned by commit or hash. No new path was found there beyond R-006 and R-008.

### 5. Integrity

- **The listening gates (F-7, High, plausible; residual on R-011, and on R-005, R-002 and R-004 by dependence).** The frozen condition, at most 8 of 12 correct, is met by chance answering (p = 0.93), by all-`A` answers, and by a listener who discriminates 70 % of the time (0.51 per round, 0.88 within three rounds). The mitigation adds control pairs, a void-round rule for misses and side bias, and more pairs, all frozen before any listening.
- **The answer key can be computed from public data (F-8, Medium, remote).** The seed is the round number, and the key travels base64-encoded in the listener's zip.
- **Calibration and validation share data (F-9, Medium).** DR-07 fits 18 curve values against the 17 T-200 pitches, and G-L3 uses the same recordings.
- **T-201's threshold is self-referential (F-29, Medium).**
- **Hand-pasted results in pilot gate records (F-32, Low).**

### 9. Scale and performance

### 11. Operational realities

### 12. CI platform coverage

- **Platforms.** All four declared platforms run `core` and `plugins`, including pluginval.
- **Host tests can pass without running (F-30, Critical, remote).** An unregistered host test passes silently because `ctest` exits 0 when it finds no tests.
- **The Standalone is never started (F-25, Low).**
- **Runner-label drift.** R-006 still covers retirement; post-delivery drift is in F-13.

### 13. Licensing of reference audio and published evidence

- **Private reference in the shared workflow (F-12, Critical, remote; residual on R-014).** The `reference` job fetches the private Philharmonia files on every push to `main` and on every pull request for the life of the repository. R-014's one-off S-REVIEW workflow check does not cover a fork's modified workflow or a later maintenance edit.
- **Licence conditions not met (F-28, Low).** CC BY change notice, CC BY-SA for derived clips, the Apache-2.0 text and the VST3 SDK's MIT notice are missing. R-016 stands.
